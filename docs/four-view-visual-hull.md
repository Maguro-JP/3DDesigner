# 4方向シルエットからの視覚殻

## 入力契約

- 正面、背面、左側面、右側面の4画像を使う。1枚絵だけから未撮影面を復元したとは扱わない。
- 4枚は同じ正投影に近いカメラ、縦位置、縮尺で用意する。画像枠内で個別に切り抜いたり、面ごとに独立して拡大縮小したりしない。
- 背面・右側面は、それぞれの面を外側から見た画像を入力する。サーバーでは背面/右側面の水平軸を反転し、同一の物体座標へそろえる。
- 入力は各面の二値シルエット。現行GUIは画像端の背景色を基準に背景を flood fill し、閉じた内側領域を前景にする。複雑な背景、輪郭の切れ、床や影は手修正が必要。

## 処理

各ボクセルを4枚すべての投影シルエットと照合する。4条件すべてに含まれるボクセルの和を視覚殻とし、露出面を三角形化してGLBへ書き出す。完成形状の側面や背面の凹凸、内部構造、材質は入力投影だけでは一意に決まらない。

GLB生成後、占有ボクセルを各面へ再投影する。方向ごとのIntersection over Union (IoU) は `交差画素 / 和集合画素`。4面の入力が同時に満たせるときのみ100%となる。画面は未達値を隠さず各面のパーセントとして表示する。

## 合格確認

- 合成した整合4方向形状で、全方向のIoUが100%。
- 高さが異なるなど矛盾する入力で、少なくとも影響方向のIoUが100%未満。
- 出力はGLB 2.0 header、JSON chunk、三角形 primitiveを含む。
- 指定された冒険者少女の画像は正面1枚のみ。現時点でこの実物の4面一致を採点する入力データは不足しているため、実物の4方向100%達成とは報告しない。

## 制約

- GUIの背景抽出は明るい単色背景を想定する簡易処理で、一般的なセグメンテーションモデルではない。
- 初期ボクセル解像度は32×64×32。IoUはこの格子へ縮小した二値マスクに対して計算する。
- 投影シルエットの一致は3D形状全体の正しさを保証しない。視覚殻は入力と矛盾しない最大体積形状の近似である。
- 100%はシルエット投影の条件であり、細部、見た目、アニメの絵柄、服としての縫合、人物リグや材質の一致を意味しない。
